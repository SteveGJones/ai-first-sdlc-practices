# Feature Proposal: kb-query resolves the relative local library path

**Proposal Number:** 212
**Status:** Complete
**Author:** Claude + Steve Jones
**Created:** 2026-10-03
**Target Branch:** `feature/kb-query-relative-path-212`
**Tracking Issue:** #212
**Plugin:** `sdlc-knowledge-base`

---

## Problem Statement

`skills/kb-query/SKILL.md` step 1 calls
`resolve_dispatch_list(global_reg, activation, Path('library'))`. The registry's
`validate_library_path` rejects non-absolute paths, so the local library is
silently skipped. The helper returns
`{"sources": [], "warnings": ["Local library: path 'library' must be absolute; skipping."], "is_empty_error": true}`
and the user only sees the generic "No knowledge base available... run kb-init"
message even though the library exists.

## Motivation

kb-query is the main read path of the knowledge base. A project with a valid
`library/` and no external libraries could not be queried at all, and the
message pointed the user at the wrong remedy.

## Proposed Solution

1. **`registry.resolve_dispatch_list`** normalises the project library path with
   `Path.absolute()` before the exists/is_dir checks. `absolute()` is used
   rather than `resolve()` so `validate_library_path` still performs its own
   strict symlink resolution and denylist check on the real path. The `local`
   source therefore always carries an absolute path.
2. **`validate_library_path` is unchanged**, as is its absolute-path test.
3. **`kb-query` SKILL.md** passes `Path('library').resolve()`, and when
   `is_empty_error` is true with a warning starting `Local library:` it shows
   that warning to the user and does not print the kb-init advice. It does the
   same for `Source '` and `Activated source '` rejection warnings, so a stale
   activation with no `library/` no longer gets the kb-init hint because the
   real cause is shown. The plugin
   copy is regenerated byte-identically from the root source.
4. **Version**: `sdlc-knowledge-base` 0.3.1 -> 0.3.2 in `plugin.json` and
   `marketplace.json`.

## Success Criteria

- `resolve_dispatch_list(..., Path("library"))` run from a project root yields a
  `local` source with an absolute path, no warnings, `is_empty_error` false.
- A relative `library` that is a symlink into a denylisted location is still
  rejected with a denylist warning.
- A relative `library/` without `_shelf-index.md` is still rejected, with the
  missing-shelf-index reason rather than "must be absolute".
- Root and plugin copies of the kb-query skill are byte-identical.
- All validators pass with zero technical debt.

## Out of Scope

- Issue #209, kept as a separate piece of work.
- Adding a new field to `DispatchList`.
- Relaxing `validate_library_path`.
