## Summary

_In progress._ Building a new SDLC-family plugin (`sdlc-agent-delegation`) with two Haiku wrapper agents — `codex-delegate` and `agy-delegate` — that let a Claude Code session delegate prompts to external agentic CLIs (OpenAI Codex, Antigravity), keep sessions open across multiple prompts, and fan out across concurrent subagents. Two continuity modes are required: id-based resume (default) and a persistent live process (opt-in).

## What Went Well

- **Tiered delegation matched cost to difficulty.** Fable for the architecture spike + two adversarial reviews (design and code), Sonnet for execution, Haiku as the shipped wrapper. Each Fable review caught real defects a cheaper pass would have missed (the `setsid`/timeout-cap BLOCKERs at design time; the `stop`-orphans-codex BLOCKER at code time).
- **End-to-end dogfood (2026-07-23) worked and paid off immediately.** Drove the real `extdel.sh` against the REAL codex + agy CLIs to review our own `turn-supervisor.pl`. The full machinery worked: submit-then-poll (`RUNNING`→`SUCCESS`), real session-id capture for BOTH CLIs, `slice` extraction, durable `./tmp` logs, `stop`, `reap`. codex returned a high-quality 10-finding review; and the run surfaced two real bugs in our own code (below).

## Dogfood Findings (2026-07-23) — follow-up work

- **DF1 (agy read-only posture is too restrictive for real work).** `agy --mode plan --sandbox` (our `read-only` mapping) **auto-denies the "command"/tool permission in headless mode**, so any task that must read a file or run a command produces **no output**. The trivial "PONG" live probe missed this because it needed no tools; a real review task exposed it. agy's own stderr suggests a `permissions.allow` settings.json allow-rule (e.g. `command(<target>)`) or `--dangerously-skip-permissions`. **Action:** rethink the agy `read-only` mapping — likely need a middle posture that permits read-only file/command access, or document that agy read-only cannot touch files.
- **DF2 (false SUCCESS on empty output).** agy exited 0 with an empty answer (tool auto-denied), and our contract reported `Status: SUCCESS`. **Action:** treat exit-0-with-empty-answer — especially when stderr matches `no output produced|auto-denied|required the .* permission` — as a distinct non-SUCCESS status (e.g. `NO_OUTPUT`/`DENIED`), so callers aren't misled.
- **DF3 (codex-found bugs in `turn-supervisor.pl`) — FIXED.** The delegated codex review flagged several real races the first Fable review and tests missed: (a) TERM/INT keep default disposition in the window between `fork` and handler install; (b) the parent can signal `-$child` before the child's `setpgrp` establishes the group → signals miss and `waitpid` can hang; (c) the timeout alarm stays armed inside the TERM/INT handler and can misclassify a stop as timeout 124; (d) a second signal during cleanup `exit 0`s mid-escalation; (e) `owner.pid` handoff truncates in place and ignores I/O failure. Sonnet applied fixes (sigprocmask block across fork→setup, parent+child setpgid, alarm(0)+IGNORE first in handler, atomic owner.pid) + a 14-test direct supervisor suite. **A SECOND Fable review of the rewrite then found a worse bug the first pass introduced/missed:** `$status` was assigned AFTER `$reaped`, so a stop racing turn completion wrote **exit.code 0 (false SUCCESS) for a failed child** — reproduced deterministically. Fixed by (1) assigning `$status` before `$reaped`, (2) a `$?`-preserving `waitpid(WNOHANG)` probe in `escalate_and_reap` and the timeout branch so an already-reaped child is never re-signalled (closes the sub-µs window), (3) `cmd_stop` waiting for the exit.code file (~8s) instead of a 5s liveness timeout that could SIGKILL the supervisor mid-escalation, plus minors (group-kill bare-pid fallback, child joins pgroup before unblocking, `$timeout` validation). **Lesson: two independent Fable reviews of the same crux file each found a distinct real defect — reviewing the fix, not just the original, mattered.** Race windows are sub-µs and not black-box-testable without production fault-injection hooks; fix verified by the review's deterministic harness + genuine-case coverage (timeout=124, stop=143, signal-death=128+sig).

- **DF4 (dogfood #2, 2026-07-25) — the orchestrator reviewed its own newest code, live.** After the `sdlc-simple-orchestration` v0.1.0 migration, drove our OWN `extdel.sh` to delegate a read-only review of the new OpenCode adapter to BOTH real codex and agy. Three wins: (1) the refactored adapter engine works end-to-end with real CLIs; (2) **DF1 validated in production** — agy read-only produced a real 1102-char review (vs the empty output in dogfood #1), confirming the `--gemini_dir` graded-posture fix holds live; (3) both platforms found real bugs. **codex flagged 2 CRITICAL security holes in the OpenCode adapter** that mock tests couldn't catch: (a) `OPENCODE_CONFIG` has LOWER precedence than a target repo's own `opencode.json`, so a project config can override our read-only denies — defeating the graded-permission model (fix: use higher-precedence `OPENCODE_CONFIG_CONTENT`); (b) project `.opencode/plugins` auto-load → arbitrary code exec even under read-only. Plus HIGH (unspecified tools default-allow → use `"*":"deny"`+allowlist; `bash:allow` bypasses webfetch denial) and agy MEDIUMs (`jq -rs` fails on any non-JSON line; missing `local` in a SOURCED adapter pollutes the engine). Logged as OpenCode-adapter hardening follow-ups (§DF4). Reviews saved to scratchpad.

## What Could Improve

- **A trivial live probe under-tested agy.** The "PONG" probe answered "does plan mode hang?" (no) but not "does plan mode allow the tools a real task needs?" (no) — DF1. Lesson: probe with a task shaped like the real workload (one that must read a file), not a no-op.

## Lessons Learned

- **Design before code, tiered delegation.** Fable for the hard architecture (Mode B lifecycle / IPC framing) and review, Sonnet for execution, Haiku for the shipped wrapper agents — matching model cost to task difficulty.

- **2026-07-26** — **Local MLX evaluation, Path A (MLX *through* OpenCode) — smoke test PASSED end-to-end, but surfaced a Path-A fairness blocker that reframes the Path B decision.** On a 32 GB M-series Mac (arm64, mlx-lm 0.31.3 in a `uv` `.venv`, `mlx-community/Qwen2.5-Coder-7B-Instruct-4bit` 4-bit), served via `mlx_lm.server`.   - **DF4 (config precedence) — SOLVED with ZERO adapter/engine change.** The opencode adapter writes a per-handle `OPENCODE_CONFIG` carrying only the read-only `permission` block. Putting the `mlx` provider block in the *global* `~/.config/opencode/opencode.jsonc` and leaving the permission block in the per-handle config **merges cleanly** — `opencode models` lists `mlx/mlx-community/Qwen2.5-Coder-7B-Instruct-4bit` under the per-handle `OPENCODE_CONFIG`, and a full read-only `opencode run` turn resolves the provider, hits the local server, and returns an answer the adapter's exact extraction jq parses. So Path A needs no code change to *reach* MLX.
  - **Wrinkle 2 (eos leak) — SOLVED with a small stop-injecting shim.** mlx_lm.server 0.31.3 leaks Qwen's `<|im_end|>` stop token into the message *content* (`` ```<|im_end|> `` glued to the closing fence), which breaks the council's `_FILE_BLOCK_RE` (it requires the closing ``` to be followed only by whitespace) → every code-block answer scored `contract-fail`. Passing an explicit `stop:["<|im_end|>"]` makes the server trim it. (Injecting `stop` via opencode model `options` instead **hung** the turn — not viable.) After the shim, the assess smoke test emits `scored` rows (was `contract-fail`), MLX correctly classified as **free wave-0** (`mlx-local` family, $0), `--max-concurrent 1`.
